Standalone STT / TTS / LLM proxy endpoints

Task: 2026-11-08-feature-standalone-stt-tts · Type: feature · Process A (agent-tracking workflow) · Date: 2026-11-08

Executive summary

Added proxy support for three upstream standalone LiveKit Agents endpoints documented by the api-livekit-docs MCP: STT (/stt/transcribe), TTS (/tts/synthesize), and LLM (/llm/chat). The backend now exposes authenticated /api/* routes that validate input, resolve optional assistant_id against the caller’s assistants, forward optional X-Provider-API-Key upstream (never logged/stored), proxy STT multipart uploads, stream TTS binary audio / LLM SSE responses, and preserve upstream usage/cost semantics. Swagger and developer docs were updated. All tests pass (195/195).

Behavior notes / decisions

Assistant ownership

assistant_id (optional) is resolved via findByLocalOrExternalId scoped to req.user._id and forwarded as the owned assistant’s external id. Unknown/unowned ids return 404 with the proxy error shape, consistent with repo conventions.

Streaming fidelity

TTS audio and LLM SSE use callExternalStream and pipe upstream bodies/headers. JSON-mode endpoints use callExternal and the central error handler. Streamed non-2xx responses are passed through for fidelity; strict {error} normalization for all streamed error bodies would require buffering.

Provider key passthrough

X-Provider-API-Key is read from the incoming request and forwarded upstream only when present. It is not stored, not written to logs, and not included in responses.
