Exotel recording proxy — feature report

2026-11-19 feature status: done

Current → Target

Current

No recording endpoint. /api/call only triggers and polls outbound calls.

No Exotel client, no Exotel env vars, no Exotel-specific validation in the service.

The pasted reference implementation used Supabase and TypeScript — neither exists in this repo.

→

Target

Authenticated POST /api/call/recording returns the Exotel MP3 bytes directly.

New src/services/exotel/ client with host allowlist, Basic auth, bounded redirects and sanitized errors.

Documented in Swagger, README env table, ARCHITECTURE and CHANGELOG. Nothing persisted.

What shipped

  • Endpoint: POST /api/call/recording with { recording_url }, behind the existing bearer-key guard. Returns binary audio with Content-Type, Content-Length, Content-Disposition and Cache-Control: no-store. Validation errors are 400; service errors keep their status.
  • Exotel client: HTTPS-only allowlist for recordings.exotel.com / recordings.<region>.exotel.com, no userinfo or explicit non-default port. Manual redirects, max 3 hops, each target revalidated. 30 s timeout, no-cache. Mandatory Basic auth from Settings.
  • Limits and safety: 100 MB success-body cap; 64 KB error-body cap; upstream XML/JSON/S3 error codes parsed and scrubbed of raw credentials, the Base64 Authorization value, full URLs and long query-token values before reaching the caller or the 5xx log.
  • Config and docs: EXOTEL_API_KEY / EXOTEL_API_TOKEN added only to src/core/config.js, mirrored in .env.example and README. Swagger gained the new path with binary content types; CHANGELOG and ARCHITECTURE updated.
  • Tests: 13 service tests and 4 route tests added, plus the new path added to the existing auth-coverage test. All run offline with an injected fetch.

Deliberately not done

  • Supabase storage, org_settings, retention metadata, GridFS — the user chose stream-only and said "no storing required".
  • Exotel webhook receiver, call-id lookup, or any change to LiveKit proxy behaviour.
  • No git commit or branch; all changes are in the working tree.

Found but not fixed / known trade-offs

  • The response is buffered up to 100 MB before res.send(Buffer), not chunked-piped. This keeps error responses clean and the size cap enforceable; concurrent large downloads use memory. Chunked streaming would need a different failure strategy.
  • WHATWG URL normalises an explicit :443 away, so that spelling is accepted. Same host and port — no security impact.
  • Credentials are mandatory per the requested behaviour even though the supplied curl works unauthenticated. If Exotel rejects Basic auth on public recording URLs, switch the client to optional auth.
  • The environment was missing three declared dependencies (zod, supertest, proxyquire). They were installed with --no-save --no-package-lock; no lockfile changed. Six pre-existing test files had been failing for this reason before any code change.
